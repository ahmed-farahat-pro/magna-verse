Reduced motion is on, so the demo is not animating. Each scenario is shown as a finished result — the question, the tools it called, the answer, the citations and the residency line. Use the three buttons above to switch between them.

1 Connected systems

It reaches into the systems that already run the business.

That answer did not come from a model’s memory. MagnaVERSE queried SAP S/4HANA directly — the live open purchase-order report — then joined the result against Primavera P6 milestone dates to work out which delays actually threaten a handover.

Connectors are read-only unless you grant otherwise, every call is named in the transcript, and every call lands in the audit trail with the user, the tier and the arguments.

2 Provenance

Every claim carries the document it came from.

An answer about contract exposure is only useful if you can defend it in a meeting. The grounding chip names the file, the sheet, the clause and the row — four sources for four assertions, each one openable.

Nothing was retrieved from the public web. The corpus is your own repository, indexed inside your network by the digital-twin context graph, and the model is only permitted to answer from what it can cite.

Company Knowledgedigital-twin context graphclause-level citationaudit trail
3 Mail over MCP

Mail is a declared tool, not a leak.

The inbox arrives through magna-mail, an MCP server registered with the workspace under an explicit scope: search_messages and get_thread. No send. No delete. Nothing cached outside the tenancy.

The mailbox stays exactly where it is. The model reads it from inside the perimeter, and the transcript records which tool ran, with which arguments, over how many messages.

What did not happen

The interesting part of that demo is the part with no events in it.

Three answers, three enterprise systems, one mailbox. Here is the network ledger for the whole run — because on a private-tier answer, the honest number is zero.

did not Call a public model API
Inference ran on Magna hardware in the customer’s tenancy — 8×H200 in Riyadh DC-1. Kimi K2 Instruct, DeepSeek V3.1, Qwen 3 235B and NVIDIA Nemotron 120B all run privately, on the same racks.
did not Move a byte across the border
Data residency is guaranteed in-country. The SAP rows, the contract PDFs and the mailbox never left the network they started in. Egress on a private-tier answer: 0 bytes.
did not Train anyone else’s model on your data
There is no vendor-side corpus. Prompts, documents and tool results stay in the tenancy; retention is policy-set by you, and the policy is enforced rather than promised.
did not Leave the answer unaccountable
Every turn carries the model, the tier, the tools called and the sources cited. Governance is policy-enforced with an audit trail your CISO can read without asking anyone for a log export.

Deployment

Same workspace. Three places to stand it up.

The demo above is one tenancy on one POD. The architecture does not change when the location does — only the perimeter around it.

01 · On-prem

In your own data centre

MagnaREACTOR racks behind your firewall, operated by your team or ours. The strictest reading of sovereignty: the GPUs are on your floor.

  • Air-gap capable
  • Customer-held keys
  • Your change-control process
02 · Sovereign cloud

In-country, single tenant

A dedicated tenancy in a Magna region with residency guaranteed in-country. Capacity elastic, jurisdiction fixed. This is what the demo is running on.

  • Five global regions
  • 24/7 managed operations
  • ISO 27001 aligned, red-team audited
03 · Edge

At the site

A compact node at a plant, a rig or a project office, for sites where the link is thin or intermittent and the answer still has to arrive.

  • Runs disconnected
  • Syncs when the link returns
  • Same policy engine, same audit trail
