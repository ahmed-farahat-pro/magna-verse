The open-source stack behind Console

MagnaVERSE Console is almost entirely hand-written vanilla JavaScript. Four third-party libraries and one webfont service are all that it depends on — and every one of them is fetched from a public CDN at runtime, which quietly contradicts the product's own sovereignty promise.

This page does three things: it documents what we already use and what each thing is actually licensed under; it picks an open-source code editor for the Code app; and it proposes a vetted shortlist of permissively-licensed libraries worth adopting next — starting with the file-export gap that blocks 11 of the 50 user flows.

The main OS file has zero dependencies

apps/app-7-console.html is 632 KB and contains no external <script> or <link> tags at all — I verified this by grep, and the count is zero. The only absolute URLs in the file are strings in sample data (localhost:5173, example.com, wikipedia.org). The window manager, Brain graph, KaTeX-style maths, Mermaid-style diagrams and the terminal are all hand-written. That is a genuine asset for a sovereignty story, and it is worth protecting deliberately rather than by accident.

Two findings worth correcting in your notes

Editor.js is Apache-2.0, not MIT

This is the one most people get wrong, and the brief was right to flag it. The core @editorjs/editorjs package is Apache-2.0 — confirmed in the LICENSE file, in package.json, and on the npm registry, all three in agreement. Its history is ISC → Apache-2.0 in August 2018; there was a request to move it to MIT that the maintainers declined in favour of Apache, which is probably where the folklore comes from. Confusingly, all eight official plugins really are MIT — so the Docs app ships a mixed-licence stack.

What Apache-2.0 adds over MIT, in practice. Three things. (1) §3 grants an express patent licence from every contributor — this is a benefit to Magna, not a cost, and it is why many corporate legal teams prefer Apache to MIT. It terminates automatically if you sue claiming the work infringes your patents. (2) §4(d) requires you to propagate a NOTICE file if the upstream has one — Editor.js has no NOTICE file, verified, so this does not trigger. (3) §4(b) requires prominent statements of change on any file you modify — only relevant if you vendor and patch it.

Net obligation for Magna: add the Apache-2.0 licence text and the Copyright © 2015-present CodeX line to a third-party attributions page. That is the same class of work the MIT dependencies already require. No copyleft, no source disclosure, no reciprocal licensing. It is not a reason to drop Editor.js.

Roboto Mono is no longer Apache-2.0

The Roboto family was historically Apache-2.0. Roboto Mono was relicensed to OFL-1.1 during 2025 and the old apache/robotomono/ path in the Google Fonts catalogue now 404s. Any inherited documentation still calling it Apache-2.0 is stale. Google's own catalogue guidance now states that only the OFL is accepted for new families. This changes nothing practical for us — OFL-1.1 permits commercial embedding and self-hosting — but it is exactly the kind of drift that makes a dated, sourced page like this one worth keeping.

The sovereignty problem: all of it comes from a public CDN

This is the most important finding in Part 1, and it is not a licensing issue at all. Every third-party asset above is fetched at runtime from cdn.jsdelivr.net or fonts.googleapis.com. For a product whose pitch is on-premises, sovereign, zero-egress AI, that is a contradiction sitting in the source:

  • An air-gapped Magna deployment would simply fail to load the Gantt, Sheets, Slides and Docs windows. There is no offline fallback.
  • Every page view leaks the client's IP address and referrer to two third parties. Google Fonts CDN linking specifically is what triggered the EU privacy complaints; the same reasoning applies under Saudi data-residency expectations.
  • Six of the loads pin @latest. That is a live supply-chain exposure — an upstream compromise or a breaking major release lands in production with no review, no lockfile and no subresource integrity hash.
  • The font files are OFL-1.1, which is a perpetual irrevocable grant. The Google Fonts API is a service governed by Google's API Terms of Service, which Google can change or withdraw. Self-hosting converts a service dependency into an asset you own.

Recommendation: vendor all five, this week

This is a one-line change per file plus a vendor/ directory, and it is the single highest ratio of credibility gained to effort spent anywhere in this document. Download each library at a pinned version, commit it, and rewrite the tags to relative paths. Do the same for the four fonts as self-hosted woff2 with a local @font-face block — remembering to ship the OFL text next to the files, which is OFL's one real redistribution condition.

Then write a THIRD-PARTY-NOTICES file containing the MIT texts, the Apache-2.0 text for Editor.js, and the four OFL texts. Once that is done, the demo runs on an air-gapped laptop and the sovereignty claim survives its first technical audit.

Part 2

An open-source IDE for the Code app

Console's Code app today renders files into a <pre> with a hand-written codeLines() highlighter. It reads local folders, shows a live preview iframe and simulates a shell — but there is no real editor: you cannot meaningfully type in it. Two separate questions follow, and they have different answers.

Option A — embed an editor component

This is the question that actually matters for Console, because the Code app is one window inside a shell, not a product of its own. Three real candidates. All three are permissively licensed, so licence is not the deciding factor here — Arabic is.

Option B — self-host a full IDE, and the licence trap in it

This is where nearly everyone gets the licensing wrong, so it is worth being exact. “VS Code is MIT” is only half true, and the half that is false is the half most people mean.

The three different legal objects called “VS Code”

  • The source at github.com/microsoft/vscode is genuinely MIT. That is real and verifiable.
  • The binaries from code.visualstudio.com are proprietary. They ship under a Microsoft EULA that forbids reverse-engineering and forbids you to “provide the software as a stand-alone offering” — which is precisely what a hosted browser IDE is. It also states telemetry can be opted out of in many scenarios but not all. For a zero-egress Saudi deployment that is disqualifying twice over.
  • “Code - OSS” is the precise name for the MIT part — the source tree built without Microsoft's branding, proprietary extensions and telemetry keys. Microsoft's own README says VS Code is “a distribution of the Code - OSS repository with Microsoft-specific customizations released under a traditional Microsoft product license.” Same repository, two different legal objects, depending on whether you build it or download it.

You may not point a self-hosted fork at Microsoft's extension marketplace

The current Visual Studio Marketplace Terms of Use (last updated September 2025) state that Marketplace Offerings “are intended for use only with In-Scope Products and Services and you may not install, reverse-engineer, import or use Marketplace Offerings in products and services except for the In-Scope Products and Services” — a list that means Microsoft's own products only. This is not a grey area.

Note the wording changed. The version widely quoted online, including in code-server's own FAQ, is from January 2019 and reads far more softly. Anyone relying on that older text in a compliance memo is working from stale language. The compliant route is Open VSX (EPL-2.0, governed by the Eclipse Foundation under a vendor-neutral working group), which is self-hostable via Docker Compose — mirror the extensions you need into an internal registry and never egress at all.

Recommendation

CodeMirror 6, and it is not close

Arabic decides it on its own. Console is being built for Saudi Arabia. Monaco has no RTL support and four open bugs about it, one of which reports the editor being invisible inside a dir="rtl" container — which is exactly how an Arabic-first shell is constructed. That is shipping a broken window on day one. CodeMirror 6 gives working Arabic from a direction: rtl declaration on a parent, with visual cursor motion, per-line direction, and bidi isolates for the mixed case every real Saudi codebase contains: Arabic comments around Latin code.

The other three reasons all point the same way. Microsoft's own answer on mobile support is the single word “No”, while CodeMirror 6 was rewritten specifically for touch — and Console must survive being resized into a small window. The measured bundle is 163 KB gzipped with syntax highlighting versus Monaco's 661 KB with no languages at all — four times smaller for strictly more function. And it is a plain ES-module library you instantiate against a DOM node, which is exactly the shape of the vanilla-JS codebase we already have.

Accept these caveats up front. No LSP out of the box — add codemirror-languageserver later if real intelligence is ever needed, and note it requires a server process per language, so defer it. One build step to produce the bundle: run it once, commit the artifact next to the other vendored files. And make certain you take CodeMirror 6, not 5 — most tutorials online are CM5 and the APIs are completely incompatible. For the compliance file: the canonical repository has moved to code.haverbeke.berlin and GitHub is now a mirror, so cite the MIT LICENSE shipped inside each npm package, since that is the artifact actually redistributed.

Second choice, for later. If Console's Code app ever has to become a real IDE — terminals, debugging, the extension ecosystem — the answer is code-server (MIT) paired with a self-hosted Open VSX, with --disable-telemetry and the gallery pointed inward. Licensing is clean and it is the most actively maintained option available. It just is not right for one window in a prototype. Pin a version and vendor the artifact rather than tracking latest: Coder Technologies already runs an AGPL-plus-proprietary split on its flagship coder/coder, so the precedent for a terms change exists even though code-server itself is cleanly MIT today.

On Arabic and RTL: the answer is discipline, not a dependency

This came out of the research more clearly than expected, so it is worth stating plainly. Console does not need an RTL library. The two obvious candidates — rtlcss (MIT) and postcss-rtlcss (Apache-2.0) — are PostCSS transforms that mechanically flip margin-left into margin-right at build time. Adopting either would mean introducing exactly the build pipeline this codebase is designed to avoid, in order to solve a problem the browser already solves.

Three platform features replace the entire category. CSS logical properties (margin-inline-start, padding-block, inset-inline, border-inline-end) have been broadly supported since around 2021 — write them once and both directions work, with no second stylesheet and no divergence between builds. The :dir(rtl) selector has been widely available since December 2023 and beats [dir="rtl"] because it matches inherited directionality. And dir="auto" on user-generated content — chat messages, file names, model output — makes the browser infer direction per string, which is essential for a mixed Arabic and English console and costs nothing.

The realistic failure mode is a developer typing margin-left out of habit. Guard it with a CI grep for (margin|padding|border|inset)-(left|right) and text-align:\s*(left|right). That is one line of CI, and it replaces a dependency, a build step and a whole class of bug. Shaping libraries like bidi-js and harfbuzzjs only earn their weight when you leave the DOM — canvas, WebGL, or PDF glyph runs.

Part 4

Recommended adoption order

Ordered by what each step unblocks, not by how interesting it is. The first two are worth more than everything after them combined.

  1. Vendor what is already there

    Pull frappe-gantt, LuckyExcel, PptxGenJS, Editor.js and its eight plugins down at pinned versions into a vendor/ directory, self-host the four fonts as woff2, and rewrite the tags to relative paths. Write the THIRD-PARTY-NOTICES file at the same time, with fonts in their own OFL section.

    Unblocks: the sovereignty claim itself — the demo runs air-gapped, no visitor IP reaches a third party, and six @latest supply-chain exposures disappear. Cost: under a day.

  2. File export — docx, then SheetJS, then jsPDF

    This is the biggest functional gap in the product by a wide margin. Add docx first: it is MIT, it works in the browser, and Word does Arabic shaping for you at render time. Then SheetJS Community for .xlsx, vendored from the vendor's own CDN rather than the stale npm package. Then jsPDF for PDF, paired with Noto Naskh Arabic.

    Unblocks: 11 of the 50 user flows — export is the single most frequent blocking capability in flows.html, more than twice the next one. Four flows are outright gaps, seven are partial.

  3. CodeMirror 6 in the Code app

    Replace the hand-rolled <pre> highlighter with a real editor. Build the bundle once and commit the artifact next to the other vendored files. Take v6, not v5.

    Unblocks: the Code app becoming genuinely usable rather than a read-only viewer — and it is the only editor choice that renders Arabic correctly, which matters more here than anywhere else.

  4. Chart.js for the missing chart renderer

    A small, well-understood addition that closes a flat gap: there is no chart renderer anywhere in the prototypes, and the live build currently answers a chart request with box-drawing characters that reflow into garbage at any other window width.

    Unblocks: two flows outright, and removes one of the most visibly embarrassing behaviours in the live product.

  5. KaTeX and highlight.js to retire hand-written rendering

    Console hand-renders both maths and syntax highlighting today. Both replacements drop in as plain script tags with no build step, and both self-host cleanly. Remember KaTeX's fonts are OFL and need their own notices section.

    Unblocks: correctness and breadth on two surfaces that currently only approximate the real thing — and deletes a meaningful amount of code we would otherwise maintain forever.

  6. The workflow canvas — Drawflow, plus @dagrejs/dagre

    For the n8n-style builder now in progress. Drawflow is the only credible vanilla, zero-dependency, no-build option at 8 kB, and dagre gives you auto-layout. Adopt Drawflow knowing you are adopting a fork you will maintain; at that size it is a reasonable trade. Study React Flow and Vue Flow for the interaction model — and remember n8n's own canvas runs on Vue Flow.

    Unblocks: the workflow builder, without touching n8n's source and without adopting a framework.

  7. Arabic: Noto Naskh Arabic and CSS logical-property discipline

    Self-host Noto Naskh, add the CI grep for physical properties, and set dir="auto" on all user and model content. No library required.

    Unblocks: Arabic that is correct on screen and correct in generated PDFs. Worth knowing how far there is to go: CSS logical properties appear zero times across every app file in the repo, and dir="rtl" appears exactly twice in total. flows.html records Arabic answers rendering left-to-right as a live defect.

  8. Later, if the product grows into it

    xterm.js when the terminal needs to attach to a real shell. Cytoscape.js if the Brain graph outgrows hand-rendering. uFuzzy at 8 kB to sharpen the Cmd+K palette. transformers.js for genuinely local embeddings — with all four egress flags set and verified on a disconnected machine. code-server only if the Code app has to become a real IDE, paired with a self-hosted Open VSX.

    Unblocks: depth rather than breadth. None of these are urgent; all of them are safe.
Part 5

Licences to avoid, or to check with legal

Magna's business model is the thing that decides these questions: a self-hosted product, shipped to a customer, for money. That combination defeats most of the reassuring arguments people make about copyleft. The single most common mistake is assuming “we only run it internally” protects you — it does not, once the software leaves your organisation as part of a deliverable.

The four families, and why each one bites

AGPL-3.0 — the internal-use defence collapses when you ship

§13 requires that if you modify the program and let users interact with it over a network, you must offer them the source of your version. People fixate on §13 and miss the simpler problem: the ordinary conveying obligations still apply. Shipping an on-premises appliance to a customer is conveying — the customer is a third party — which triggers source-disclosure for the covered work and anything forming a single combined work with it. “We only self-host it internally” is a good argument right up until the moment the product is delivered, which is Magna's entire model.

Verified in this space: Grafana (moved from Apache-2.0 in 2021), Nextcloud server, Plausible, ONLYOFFICE server, Firecrawl, and Windmill's core — worth knowing since Windmill is an obvious thing to reach for while building a workflow builder. Metabase splits AGPL from a commercial enterprise/ tree; Mattermost is a three-way split where, notably, binaries compiled by Mattermost Inc. are MIT even though the source is AGPL.

Three corrections worth making, because these are widely misfiled as AGPL and are not: Rocket.Chat is MIT at root, Chatwoot is MIT at root — both open-core with paid enterprise/ directories — and Cal.com's repository is now plain MIT (it redirects to cal.diy, with the commercial product taken closed-source separately).

SSPL — reaches your entire operational stack, not just the program

Two differences from AGPL, and both matter. First, the trigger is offering the functionality as a service — modification is not required. Second, and far more serious, the scope: SSPL demands the source not only of the program but of “all programs that you use to make the Program available as a service” — its own text enumerates management software, user interfaces, APIs, automation, monitoring, backup, storage and hosting software. It reaches code with no derivative-work relationship to the licensed program at all. OSI never approved it; MongoDB submitted it twice and withdrew it.

Get the current state right, because it has moved twice. MongoDB is SSPL and has not reverted. But Elasticsearch and Kibana are now triple-licensed — AGPL-3.0 or SSPL or Elastic License 2.0, your choice, with x-pack/ solely ELv2. And Redis is tri-licensed as of Redis 8: 7.2 and earlier were BSD-3-Clause, 7.4 was RSALv2 or SSPL, and 8.0+ adds AGPLv3 as an option.

Practical consequence: where AGPL is on the menu you can elect it and be governed by AGPL's narrower clause instead of SSPL's stack-wide one. Record that election in writing in the licence register. Silently defaulting to “it's SSPL, we can't use it” is a self-inflicted wound.

BSL / BUSL-1.1 — a clock that restarts with every version you upgrade to

BSL grants only non-production use unless an Additional Use Grant says otherwise, then converts to a real open-source licence on a Change Date. The detail people miss: the Change Date runs per version. The build you ship today converts four years from its publication — upgrade next quarter and the clock restarts. The Additional Use Grant is drafted per product and is where all the risk lives.

Verified: Terraform and Vault are BUSL-1.1 converting to MPL-2.0 after four years, and their licensor is now IBM following the acquisition; their grant permits production use unless you offer the software to third parties to compete with the paid version. OpenTofu, the Terraform fork, is plain MPL-2.0 and is the correct choice if you need those semantics in a shipped product. MariaDB MaxScale's grant is bluntly quantitative — fewer than three production server instances.

Two live corrections. CockroachDB is no longer BSL at all — it is now a proprietary licence with a mandatory licence key, mandatory telemetry, and no Change Date whatsoever. It never becomes open source. Citing it as a BSL example is now actively misleading. And Sentry uses FSL, not BSL: everything is permitted except a “Competing Use”, converting to Apache-2.0 after two years rather than four.

fair-code and “source available” — the category with no SPDX identifier

n8n's Sustainable Use License restricts you to “your own internal business purposes or… non-commercial or personal use”, and permits distribution only free of charge and non-commercially. For Magna both halves fail at once: shipping to a customer is not your own internal purpose, and you are not doing it free. Embedding n8n in a product you sell requires a separate commercial agreement. Note also that non-master branches are not licensed at all, and .ee. files fall under a separate enterprise licence.

The n8n-adjacent alternatives are not uniformly safe either. Of the four a team would naturally evaluate: Activepieces (MIT core) and Flowise (Apache-2.0 core) survive this model provided the ee/enterprise directories are excluded from the build and that exclusion is enforced in CI. Windmill's core is AGPL. Dify uses a modified Apache-2.0 that adds two conditions fatal here: multi-tenant service is prohibited without written authorisation, and you may not remove or modify the Dify logo or copyright information — which forecloses white-labelling.

Two more in this family worth naming. Open WebUI is especially relevant, since it is the closest thing to what Console is: it is BSD-3-Clause plus a branding clause that prohibits altering or removing Open WebUI branding, with an exception only below 50 users per 30 days. A white-labelled Magna product built on it would be in breach. And Directus quietly moved to a bespoke “Monospace Sustainable Core License” whose redistribution clause forbids imposing a licence fee for the granted rights — in direct tension with shipping it inside a paid product. Its licence lives in a lowercase license file, which is exactly how scanners miss it.

“Free for non-commercial use” — the quietest trap of all

These carry no copyleft, so no scanner flags them, and they are routinely assumed free because a free tier exists.

  • Handsontable — free use is limited to personal or evaluation purposes outside production. Covered in Part 3; it also carries a non-compete clause.
  • Highcharts — not free for commercial use, and this is misunderstood constantly. It is a proprietary Highsoft licence in three tiers, and Magna's model needs the OEM tier because the product is distributed to third parties. It is not CC BY-NC, despite the folklore. Its npm licence field is a bare URL, which scanners frequently mis-tag as permissive.
  • Syncfusion — the free Community License is gated on hard thresholds: under $1M revenue, at most 5 developers and 10 employees. A Saudi enterprise is outside every one of them.
  • Kendo UI — embedding is permitted but you must display a copyright message visible to end users, so it cannot be fully white-labelled; and your customers need their own developer licences if they build UI with it.
  • DevExtreme — per-developer subscription required to build commercial applications “whether sold or distributed free-of-charge”, though distribution is then royalty-free.

One that is fine, but not as free as it looks: Font Awesome

Worth a line because an icon set is an easy unexamined choice. Font Awesome Free splits three ways within itself: the icons as SVG and JS are CC-BY-4.0 and therefore require attribution; the web and desktop fonts are OFL-1.1 with “Font Awesome” as a Reserved Font Name; and only the remaining non-icon, non-font code is MIT. Usable in a shipped proprietary product, but it obliges an attribution surface, and CC-BY is content rather than code — many corporate policies route it to a different review path. Tabler Icons, one MIT notice for the whole set, avoids all of this.

Make the licence gate fail closed

The pattern running through this entire section: almost every trap declares a non-SPDX licence string — SEE LICENSE IN LICENSE.txt, a bare URL, LicenseRef-LICENSE, Commercial, or nothing at all. A CI gate configured to reject a denylist of known-bad SPDX identifiers will wave every one of them straight through.

Configure the gate to fail on any unrecognised or absent licence string, not just on a copyleft denylist. Then add an explicit package denylist for the specific traps found here: handsontable, hyperformula, ag-grid-enterprise, @univerjs-pro/*, @tiptap-pro/*, arabic-reshaper, highcharts, and elkjs pending legal review. Several of these traps also hide in non-standard filenames — license.txt lowercase, LICENCE.md with British spelling, License with no extension — which is why GitHub's own detector reports NOASSERTION for a surprising number of them.
