The one thing that is now provably false

“Egress today: 0 bytes”

The Sovereignty widget prints this in the corner of every screen. Beside it, the Connections app — which reads the machine's real configuration — lists four external sources: three cloud model providers and API Studio. One of those two screens is wrong, and it is the counter. There is no byte accounting anywhere in the system; the number is a literal in the HTML, in ten places.

This matters more than any other item here. Sovereignty is the product's central claim, and this is the only number on screen that states it numerically.

Bugs found by chasing symptoms

Each of these was reported as one problem and turned out to be several. They are listed because the pattern matters: in every case the system reported success while doing nothing.

SymptomActual cause
“Uninstall doesn't remove the app” Removal had never run. The guard compared a directory path against a list of package names, never matched, and returned noop: true — while the UI said “Removed.” Underneath, pnpm needs a directory for add and a package name for remove.
“Pick a model” with a model picked Three bugs stacked: the executor dropped params.model; the stream chunk type was text-delta, not text; and listModels() was called with the display name instead of the route id, which silently deleted Ollama and DeepSeek from the picker.
“The model doesn't write to the file” The Content field defaulted to empty, so the node wrote 0 bytes and reported success. It now defaults to {{main}} — the value from the node you just connected.
“Clicking a file does nothing” The open handler lived only on a 20px button revealed on hover. Rename and new-file naming were broken the same way and fell through to a Chrome prompt().
A plugin vanished from the profile An npm install inside a linked package left a lockfile; the next pnpm add re-resolved and dropped an unrelated plugin. Caught by a smoke test, not by a user.

The pattern worth naming

Every bug above is the same failure: something reported success while doing nothing. An empty file written, an empty model response returned, a removal that removed nothing, a provider list missing half its entries. None of them threw. All of them looked fine on screen.

That is the argument for the rule this build has followed throughout: a screen must show what the system can actually observe, and when it cannot observe something it must say so rather than round it to the comfortable answer.
