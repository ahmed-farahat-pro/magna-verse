Design direction · nothing here is built

Console already works. This is the argument for how it should look.

Console has thirty-one apps, four Spaces, a Brain, a dock, a widget rail and twelve themes. What it does not have is a visual system — a single set of rules about surface, light, motion and colour that every one of those pieces obeys. Right now depth is decided per component, glass is applied everywhere by default, every window is lit identically, and the durations in the stylesheet run from 90ms to 600ms with no scale behind them.

This page proposes that system. Every proposal below is a live specimen — real HTML, CSS and canvas running in this page, in both themes, so you can look at it rather than read about it. Where something would cost frame budget, it says so in the same box.

01

Surface and depth, as one system

Console's stylesheet has one --glass token doing five different jobs, and backdrop-filter: saturate(1.5) blur(26px) on the menu bar, the dock, every window, every popover and every widget card. Visually that means everything sits at the same distance from you. Technically it means a dozen simultaneous backdrop snapshots — which is exactly the class of problem that forced the full-viewport blur out of the ⌘K switcher.

The fix is not "less glass". It is giving each level of the stack a fixed identity — a surface colour, a border, and a shadow that always travel together — and reserving translucency for the one thing translucency should mean: this is floating above the desktop.

Why
Every shadow here is two shadows — a tight contact shadow (1–3px, higher alpha) and a wide ambient shadow (10–70px, low alpha). One blurred drop shadow always reads as a sticker; two read as an object resting on something. And every raised surface carries inset 0 1px 0 var(--rim-top): light comes from above, so the top edge is brighter than the bottom. Console currently draws a uniform rgba(255,255,255,.10) all the way around, which is why windows look printed rather than placed.
Effort
Cheap. This is a token rename plus five utility classes. No JS. It removes work from the compositor rather than adding it.

In "glass on everything", the popover over the window is mud — it is blurring an already-blurred surface, so it has no edge and no colour of its own. 02

Light — one source, and a window that knows it is focused

Console has colour but it does not have light. The focused window today gets a slightly stronger shadow and a slightly brighter border; that is the whole signal. In a thirty-one-app OS where four windows are open at once, that is not enough to find your place, and it is a wasted opportunity — focus is the one moment where a little colour is earned.

The proposal is a single key light at the top of the viewport that every shadow offset derives from, plus a focus light that only the front window receives. Nothing glows. Nothing pulses.

Focused vs idle

Spec
Focused: box-shadow:inset 0 1.5px 0 color-mix(in srgb,var(--tint) 55%,transparent) on the title bar, a linear-gradient wash at 9% over the top 96px, --sh-4. Idle: a ::after scrim of var(--bg) at 16%, --sh-2. Both are static CSS driven by the .focused class Console already sets.
Warning
watch this The obvious implementation of "idle windows are desaturated" is filter: saturate(.88). Do not. filter on a positioned element promotes it to its own layer and makes it a containing block for its fixed-position descendants — which will break dropdowns inside windows. The scrim overlay costs nothing and cannot break layout.

Rule
Bloom is allowed in exactly one situation: an element that is emitting — an agent mid-run, the Ask AI orb while thinking, a dock tile whose app is doing work. Never on hover, never on text, never on more than one element at a time. Max 8% alpha, radius at least 2.5× the element. Use a radial-gradient on a pseudo-element — never filter:blur(), which is a separate render pass.

Caustics — a slow luminance drift, not water

amplitude 0.06
0.06
Taste
The tasteful version of "caustics" in an OS is not a pool-bottom ripple. It is a very low-frequency luminance variation moving at roughly 0.02 px per frame — slow enough that you never catch it moving, present enough that the wallpaper is never flat. Push the slider past ~0.12 and it becomes a lava lamp.
Cost
every frame This canvas runs at 24fps at half resolution and stops entirely when scrolled out of view. On a full 2560px desktop it should render into a 1× offscreen buffer at 12fps and be blitted — or be replaced by the pure-CSS ground in §03 whenever an overlay is animating over it.
03

The wallpaper as a living system

Console's wallpaper today is a radial gradient, two drifting blur blobs, a 52px grid, the Magna mark at 16% and a neural canvas. It is already more alive than most desktops. The problem is that none of it means anything — it drifts on a timer, not on the state of the machine.

A desktop that is the front end of a sovereign AI cluster has, sitting unused, the most interesting data source any wallpaper has ever had: GPU load, agent activity, egress, the hour, the prayer times. Three proposals, in increasing cost.

The idea
Contour lines from a value-noise field, like a survey map of the Tuwaiq escarpment. Four bindings: hour drives hue and the horizon height, GPU load drives turbulence, agent count drives how many contours carry a travelling highlight — and egress drives the one that matters. While egress is zero every contour is a closed loop: nothing leaves the frame. Move the egress slider and one contour opens and runs off the edge. That is Console's central promise, rendered as a picture you can read from across the room, and it beats the Egress today: 0 bytes line in the widget rail because you cannot help seeing it.
Cost
every frame Honest numbers: at 1000×562 half-res this is ~3–5ms per frame in JS. It must run at 20fps, not 60, must stop on document.hidden, and must be frozen to a still the moment any window is being dragged or the ⌘K switcher opens. Budget it as "the wallpaper is a video that pauses whenever the user touches anything".
Risk
Medium. The failure mode is legibility — contours behind desktop icon labels. Mitigation: the field is drawn at 26% opacity over the flat ground, and the top 15% (under the menu bar) and bottom 18% (under the dock) are damped.

The idea
Arabic geometry in software almost always goes wrong the same way: the pattern is drawn as lines on the surface, at full contrast, as decoration. Here the tessellation is never a line — it is the shape of a light source inside the ground, at 3–5% contrast. The test for taste: at arm's length on a laptop you should not be able to say for certain whether it is there. It anchors at the qibla-facing corner and rotates one degree per hour. Push the contrast slider to 20% to see exactly what to avoid.
Prayer time
The pattern's brightness eases up over the four minutes before each prayer and eases back down after. Ambient, never modal. No toast, no sound, no dialog — the room simply gets slightly warmer. Drag the second slider toward zero.
Cost
idle The tessellation is rasterised once into an offscreen canvas at load and then only transformed. Per-frame cost is a single drawImage — or zero, if you translate a <canvas> element with CSS instead. Best value on this page.

Four gradients and three custom properties. JS touches it once a minute to set --sun and --h1/--h2/--h3, then never again. This is the answer to Console's compositing problem: whenever an overlay is animating — the ⌘K switcher, a space switch, a window drag — swap the live wallpaper for this one. Nobody will notice the swap, and the backdrop-filter layers above it become cacheable.

Riyadh
The specifics that make this local rather than generic: the shamal haze — a warm, low-saturation veil that thickens between 14:00 and 18:00; Tuwaiq limestone as the light theme's ground rather than a neutral grey; and the actual colour of a Riyadh dusk, which is a fast magenta-into-indigo, not the slow orange of a coastal sunset. Drag through 17:00–19:00 and watch it turn.
Avoid
Camel silhouettes, illustrated dunes, palm trees, mosque domes, and the flag's green used as a UI colour. Every one of those reads as a tourism board. Sovereignty should look like precision and locality, not like iconography.
04

Motion language

Console's stylesheet currently contains transitions at .12s, .15s, .18s, .2s and .3s, plus animations at 300ms, 180ms and 600ms, and a dock hover on cubic-bezier(.2,.9,.3,1.5) — that trailing 1.5 is an overshoot. Overshoot on a single playful button is charming. Overshoot on a dock holding thirty-one enterprise apps makes the product feel like a toy.

Six durations. Four curves. Nothing else gets written.

Rules
1. An exit is 0.6× its enter. 2. Longer distance gets a longer duration, never a different curve. 3. Animate opacity and transform only — never width, height, top, left, filter or backdrop-filter. 4. Stagger is 20ms and caps at six items; the seventh onward arrive together. 5. If it happens on every keystroke it gets no animation at all. 6. No spring, no overshoot, anywhere in the OS.

Typography and density

An OS type scale is not a website type scale. Almost all of it lives between 11px and 14px, and its job is to stay readable at density, next to numbers, in two writing systems. Console currently uses roughly fourteen distinct sizes between 10px and 26px. That is not a scale, it is a history.

Seven roles. Six sizes. System stacks only — no webfont, ever, in a product that must run air-gapped.

Colour — three families that must never be confused

Console's twelve themes each redefine --accent and --cyan. But --cyan is also the hover glow and several data colours, which means picking the "Masonry" theme quietly changes the meaning of a hover. The fix is to split colour into three families and let only one of them be themeable.

The three families

token split
Rule
Brand (--accent, #D71920, plus the mark's own gradients) appears on the mark, the one primary action in a view, and destructive confirmation. It is never a status colour — a red chip that might mean "Magna" or might mean "failed" is a chip that means nothing. Semantic is identical across all twelve themes. Tint is the only themeable family, and it is allowed on exactly four things: the wallpaper, text selection, the focus ring, and the space pips.

07

The AI-futuristic layer, done with restraint

This is the part most likely to go wrong, so here is the thesis first: the futurism has to come from behaviour, not from decoration. A surface that responds to what the machine is actually doing looks more advanced than a surface covered in glowing lines — and it ages, because it is describing something true rather than quoting a film.

Five moves, then the list of things not to build.

1 — Thinking has one vocabulary, at every scale

SVG dashoffset · GPU
14px — inline reading 12 chunks In a message, a cell, a table row.
22px — window chrome This window's agent is working. Replaces a title-bar spinner.
58px — the orb Ask AI, the companion, the boot screen.
what to delete Spinners and three bouncing dots say nothing and belong to every other product.
The move
It is not just "use the logo instead of a spinner" — the brief already asks for that. It is that the draw speed encodes progress. A slow, even 1.9s loop means working. The loop accelerating to 0.85s means the model is closing out. A single completed draw that then holds means done. Three states, one shape, no text needed, and it reads identically at 14px and at 58px because a two-stroke mark has no detail to lose.

2 — Agent activity as light, not as a badge

• • 3 •
Split
Two different facts are wearing the same red dot in Console today. A count ("3 unread") is a thing you must clear — it earns a badge. Activity ("this agent is running right now") is ambient — it should be a soft under-light in that agent's colour and a brighter top hairline on its window. In the "Badges" mode above, five red dots compete and none of them tells you what is happening. In "Light" mode you can see at a glance that three things are working and one thing wants you.
Cost
Cheap. A box-shadow and a 3px pseudo-element per running tile. 0 frame cost — no animation is needed; the light either is or is not.

5 — The settle

The move
When a batch of background work completes, the whole desktop's ambient light rises about 3% and returns over 700ms. You feel that something finished without reading anything, and it is the only place in the OS where the entire screen responds at once — which is what makes it legible as "everything is done" rather than "one thing happened".
Cost
one-off A single opacity transition on one wallpaper overlay div, 700ms, once per batch. Do not implement it as a filter:brightness() on the desktop root — that repaints every window underneath.

What I would ship, and in what order

Recommendation

Riyadh Dusk — wearing Quiet Instrument's chrome rules.

Of the three, Deep Field is the one that will win the meeting and lose the year. It is the most photogenic and it is also the direction that every AI product on earth is already walking toward; in eighteen months it will read as dated, and it is the most expensive to run. Keep it, but scope it to the Research space only, where the Brain graph as a ground is literally descriptive rather than decorative.

Quiet Instrument is right about the chrome and wrong about the ground. Opaque window bodies, three glass surfaces, no springs, no hover glows, a dock that does not bounce — all of that should be adopted wholesale. But a ground with no hue gives Console nothing that a well-made internal tool does not already have.

So: Riyadh Dusk. The chrome is quiet and disciplined; the identity lives in the ground, where it costs nothing to be beautiful and where it can carry real state. It is the only one of the three that a competitor cannot ship next month, because it is built from something they do not have — a machine in Riyadh, an hour, a prayer time, and an egress figure that is zero.

  1. Week 1 — free wins. Elevation ladder, two-part shadows, top rim light, opaque window bodies, the motion scale sweep, tabular numerals, the residency fill/outline change, and the sovereignty strip. None of it costs a frame and all of it is visible immediately.
  2. Week 2 — light and ground. The focus light, the colour family split, and W3, the CSS ground with the solar model. At this point the desktop already looks like a different product.
  3. Week 3–4 — the identity. W2, girih-as-light, drawn once into an offscreen canvas. Then the mark-as-thinking at three speeds and agent activity as light.
  4. Later, and only with a frame budget in hand. W1, the closed field — the strongest single idea on this page and the one most likely to be built badly. It needs the freeze-on-interaction machinery before it needs the art.
  5. Deliberately last. The Arabic sweep. It is three days of unglamorous find-and-replace across 13,000 lines and it will feel like nothing shipped — but the product is for Saudi Arabia and every day it is deferred, more hard-coded left values are written.

What I deliberately did not propose

  • Any new feature. The forty-one ideas in the backlog are all functional; not one of them is about how the thing looks. This page stays strictly in the visual layer, and none of it overlaps that list.
  • A thirteenth theme. The twelve that exist are layouts plus an accent, which is a different axis from a look. Adding more accents does not fix that; splitting brand from tint does.
  • Replacing the traffic-light buttons with something branded. They are borrowed macOS colours and they are slightly off-brand — and they are also the one control every user already knows. Not worth it.
  • 3D window transforms, tilt, or more parallax. Console already has holographic 3-plane parallax. Adding depth theatre on top of a depth system that is not yet coherent would make it worse, not better.
  • A sound design layer. Real, and out of scope for a page about looking.

Things I would flag before anyone builds this

found while using Console
  • Light theme is not finished. Switch Console to light and open Docs: the desktop, dock and widget rail invert correctly, but the document surface stays dark. Several app bodies are hard-coded rather than tokenised. Any visual system is worthless until that is true in both themes — this should be fixed before any of the above.
  • The wallpaper loses all identity in light mode. Dark gets the glow, the grid, the mark and the neural field; light gets a pale grey gradient. Light users currently get a different, worse product.
  • The twelve themes only set --bg, --accent and --cyan. The surfaces, lines and shadows stay dark-tuned, so several themes have windows that do not belong to their own background. The elevation ladder fixes this by making surfaces derive from the ground.
  • --tx-3 at #787E8D fails AA on the dark glass and it is carrying Agent Feed timestamps, widget sub-lines and icon labels. One hex change.
  • The cyan hover drop-shadow on dock, menu-bar and tab icons is a filter pass on every hovered icon, it is off-brand, and its colour is themeable — so what a hover means changes with the theme.
