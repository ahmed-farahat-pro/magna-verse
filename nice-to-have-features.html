01

Why this is hard

Before adding flashy features, foundational issues make Arabic AI experiences feel second-class next to English-first tools. These need solving first — everything else is built on top of them.

Tokenization inefficiency

Arabic script typically consumes 2–4× more tokens per word than English, silently eating context window and raising cost per conversation. Worth evaluating a custom Arabic-optimized tokenizer or byte-level fallback rather than a generic multilingual one.

Dialect vs. Modern Standard Arabic

Users write in Egyptian, Gulf, Levantine or Maghrebi dialect, but most models default to overly formal MSA even for casual input. A dialect-detection layer that matches the user's register would feel dramatically more natural.

Diacritics (tashkeel) handling

Most Arabic text online is undiacritized, causing ambiguity between words with identical letters. Optional automatic diacritization for generated text would help children's content, poetry and religious text specifically.

Mixed RTL/LTR rendering

Arabic sentences containing English brand names, numbers, code or emails frequently break visual order — cursor jumps, flipped punctuation, reversed numbers. Needs dedicated QA with real mixed-script test cases, not just RTL CSS flipping.

Morphological richness

Arabic root-pattern morphology means naive keyword search misses inflected forms. Knowledge-base retrieval needs Arabic-tuned stemming/lemmatization (e.g. an ISRI stemmer or a proper morphological analyzer), not literal string matching.

Voice quality

Azure TTS/Whisper is a solid baseline, but Arabic STT accuracy drops sharply with dialects and background noise, and Arabic TTS often sounds robotic next to natural-sounding English. Worth evaluating specialized Arabic voice vendors or dialect-labeled fine-tuning.

⚠ Cultural & religious sensitivity, Hijri calendar

Scheduling, dates and content generation should natively support the Hijri calendar alongside Gregorian, and content-safety guardrails should be tuned to regional cultural norms rather than a translated Western guardrail set.

03

Arabic-specific features

primary differentiator

The single biggest lever — features no major English-first competitor handles well, because they aren't built for Arabic-speaking users first.

Dialect-aware response mode

An explicit toggle or auto-detected setting — "Respond in Modern Standard Arabic" vs. "Respond in my dialect," with sub-options for Khaleeji, Egyptian, Levantine, Maghrebi. Solves the single biggest daily complaint Arabic users have with existing chatbots.

Arabizi transliteration bridge

Many Gulf/Levantine users type Arabic using Latin letters on mobile ("3arabi" for Arabic). Recognizing and responding naturally to Arabizi input is genuinely unique — no major competitor handles this well today.

Native Hijri/Gregorian dual calendar

Across scheduling, heartbeat automations and cron jobs — dates shown and accepted in both calendars, not Gregorian-only with a translated label.

Arabic-first OCR & ingestion

Tuned for Arabic fonts, calligraphy styles and scanned government/legal documents. The Knowledge feature already supports OCR toggling — Arabic accuracy should be a headline benchmark, not an afterthought.

RTL rich-text editor

For the canvas/document features — correct handling of mixed Arabic/English/numeral editing, which is a weak spot industry-wide, not just here.

Regional Arabic voice personas

Saudi, Egyptian, Levantine accent options for TTS output, instead of one generic Arabic voice for the entire region.

Arabic-first prompt templates

Expanding the existing Analyze/Automate/Create/Simulate chips with region-specific templates: Zakat/finance calculations, per-country government service Q&A, Arabic contract/legal drafting, Arabic SEO content.

Auto-diacritization

Optional automatic tashkeel for generated text — most useful for children's content, poetry, and any text where undiacritized Arabic is genuinely ambiguous.

⚠ Classical Arabic & religious text mode — high risk if done wrong

Careful, sourced handling of Quranic verses, Hadith and classical poetry with correct diacritics and citation of authentic sources. This needs real subject-matter review, not just model generation — a scholarly review workflow, not a fully automated pipeline. Flagging this as an area worth extra caution and a human review layer before shipping anything.

04

Platform & enterprise features

Features that strengthen the competitive position specifically against consumer-focused ChatGPT and Claude, by leaning into enterprise governance and regional integration depth.

Visible memory management UI

List, edit and delete individual remembered facts — not just an on/off toggle.

Real-time collaborative canvas

Multi-user editing of generated docs and slides, building on the canvas endpoints that already exist but are currently inactive.

Sandboxed code execution

Data analysis, chart rendering, file transformation — currently listed as "Upcoming/disabled" and worth activating.

Inline citations

For knowledge-base-sourced answers, clickable back to the exact source chunk or page.

Per-skill/per-tool audit log

Pairing the existing Permissions auto/allow settings with a searchable audit log of every tool call made by every sub-agent — a strong enterprise-governance sell against consumer-focused competitors.

Model routing transparency

Show which underlying model handled each response and why (cost vs. quality routing), extending the Usage dashboard's per-model breakdown into a live indicator inside the chat itself.

Marketplace for regional MCP connectors

Region-specific integrations — local ERPs, government e-service APIs, regional payment and logistics providers common in GCC markets. A strategic moat global competitors are structurally slower to prioritize.
