Design decision · MagnaVERSE Console · system announcer

The Console should tell you what it just did.

Right now it tells you four times, in four voices, and one of them is wrong about who did it. This page proposes one event grammar and one copy standard, then offers five genuinely different surfaces built on top of them — a narrator, a presence, a ledger, a card stack and an ambient light. All five are wired to one live event bus further down, so you can fire an event once and watch every option answer it at the same time.

The Magna mark is the announcer. It is the brand's one moment of colour and the one thing on screen that is allowed to be saturated — so it carries identity and state, and never carries status. Status is carried by five semantic colours that are deliberately quieter than the mark.

00 · Why this is needed

The plumbing is already there. The design is not.

Console already has everything a notification system needs. toast(msg, ms) fires a transient line and — correctly — calls notifPush() so a permanent record exists for every single one. #notifPanel is a proper slide-over with an unread badge on the clock. #thoughtStream gives the OS an inner monologue. The Agent Feed widget reports agent work in the right-hand column. focusMode() already quiets toasts while still logging them. Four surfaces, all working.

What is missing is the layer underneath: a shared definition of what an event is. Nothing in the code says what class an event belongs to, how urgent it is, who performed it, what it touched, whether it can be undone, or which surface owns it. So each surface invents its own answer. Here is the same real event — the Mail Triage agent finishing a classification pass — as Console renders it today, live, in all four places at once.

toast()

Mail Triage Agent: 3 vendor mails classified: 2 routine, 1 asks for a variation notice — escalated to you.
Agent name as a prefix, colon, then a second colon inside the sentence. 108 characters, no past-tense verb, no action.

#thoughtStream

Mail agent · 3 vendor mails classified · 1 escalated to you
Same event, different agent name ("Mail agent" vs "Mail Triage Agent"), telegraphic, middot-separated, no punctuation, and a different count.

#notifPanel row

Console — Mail Triage Agent: 3 vendor mails classified: 2 routine, 1 asks for a variation notice — escalated to you.
Because toasts push with kind:"toast" and no title, the Centre attributes the agent's work to "Console". The sender is wrong.

Agent Feed widget

Mail Triage Agent — 3 vendor mails classified: 2 routine, 1 asks for a variation notice — escalated to you. 01:26 PM
Byte-identical to the toast, attributed correctly this time — so the Notification Centre shows the same event twice, under two different senders.

This is reproducible in the live build. Open apps/app-7-console.html, explore as a guest, wait for the mail triage event, then open the Notification Centre. The event is listed twice — once as Console and once as Mail Triage Agent — because the toast and the agent feed each pushed their own record and nothing deduplicates them. There is no event identity, so there is nothing to deduplicate on.

Three different things share one stream

Console's notification log currently mixes reports ("Document saved."), responses to something you just pressed ("Nothing to undo.", "Open a file first.") and tips ("Signed in. Press ⌘K to switch desktops…").

Only reports are announcements. A response belongs next to the control you pressed; a tip belongs in onboarding. Splitting these three removes roughly a third of the traffic before any design work happens.

Some copy is already right

The standard proposed below is not invented — it is extracted from the best strings Console already ships:

"Downloaded. The file never left your browser."
"Automation created. It has no write scope yet."
"Cancelled. Nothing was written."

Each is: past tense, names the object, then states the consequence — including the absence of one. That is the whole standard.

And some is not

"Discarded." — discarded what?
"Duplicated." — which file, where to?
"Run finished — …" — which run, what changed?
"Nothing to undo." — a response, not an event.

In an environment where agents act on your behalf while you are not looking, an announcement with no object is worse than silence: it tells you something happened and denies you the ability to check it.

House position, honoured. desktop-vision.html §07 argues that a count ("3 unread") earns a badge because it is a thing you must clear, while activity ("this agent is running") is ambient and should be soft light in the agent's colour, not a red dot. Every option below is scored against that rule. Options 2 and 5 are the direct expression of it. Option 4 partially contradicts it, and §04 says exactly why the contradiction is earned.
01 · One event, one shape

Five classes. Four of them already have a colour in Console.

Every announcement is one object. The surfaces are five ways of rendering it — they never invent content, they only choose how much of it to show. This is what makes the simulator possible, and it is what makes it possible to ship two surfaces without them disagreeing.

The event

{
  id:        "ev_8f21",        // stable — dedupes across surfaces
  cls:       "wrote",          // done | needs | blocked | wrote | result
  actor:     "Mail agent",     // ONE canonical name, everywhere
  app:       "mail",           // which dock icon lights
  text:      "Drafted a reply to Al-Rashid…",
  object:    { kind:"draft", id:"d_119" },
  residency: "private",        // private | egress | blocked
  reversible: true,
  needsHuman: false,
  actions:   [{ label:"Open draft" }, { label:"Undo", undo:true }],
  ts:        1755598...
}

Two fields do most of the work. id makes the duplicate-row bug impossible. needsHuman is the only thing that decides whether an announcement is allowed to interrupt — in any surface, in any option.

The red problem, stated plainly. The Magna mark contains green, teal, blue and red, and the brand accent is crimson #D71920. So every conventional status hue collides with the brand somewhere. The resolution is threefold: hue carries class; fill weight carries severity (only blocked gets a filled ground); and position keeps them apart — the mark always sits in the sender slot, the class colour always sits in the rail or dot, and the two never occupy the same 8 pixels. --ev-blocked is a darker, browner red than the brand crimson on purpose, and it never ships without both an icon and the word "Blocked", so hue is never doing the job alone.
02 · The copy standard

Say what you did, to what, and what it means for me.

This matters more than any of the five visual options, and it is the part that ships regardless of which one you pick. A beautifully animated surface saying "Action completed" is worse than a plain grey line saying "Drafted a reply to Al-Rashid. Not sent."

Seven rules

  1. Past tense, active, the doer first. The system did it — say so. "Indexed 12 chunks", never "12 chunks were indexed" and never "Indexing complete".
  2. Name the object. Never a bare verb. "Discarded." fails; "Discarded the draft to Al-Rashid." passes.
  3. State the consequence — especially its absence. "Not sent." "Nothing was written." "Nothing left Riyadh." In a sovereign environment, what didn't happen is the reassuring half.
  4. One sentence, then one qualifier. Target 90 characters before the full stop, 140 in total. If it needs more, it is a result and belongs in a document, not a notification.
  5. No adjectives for the machine's own work. No "Successfully", no "Great news", no emoji, no exclamation mark. The machine does not congratulate itself.
  6. If a human must act, the ask is the last clause. "…Irreversible — needs your sign-off." The reader should be able to stop at the full stop and still know what is wanted.
  7. Residency is a tag, not prose. "Private" is a chip. It only enters the sentence when it changed — a block, an egress, a tier switch.
Arabic note. Console is bilingual. Rules 1 and 2 survive translation intact — Arabic verb-initial past tense (صاغَ رداً على الراشد) is the natural register for this. Rule 4's character budget must be measured in Arabic too; it typically runs 10–15% shorter, which is headroom, not a problem.

03 · The five options

Five answers to "how should the OS tell me what it did".

Each is shown inside the same miniature Console — same menu bar, same window, same dock — so no option gets a home advantage. They are live right now: every stage on this page is already subscribed to the simulator's bus, so the specimens below react as soon as you fire anything in §04. Use the buttons under each one to feel it on its own first.

01

The narrator

One refined line, the mark beside it, the system speaking in plain past tense. It says the thing, then it goes. No history on screen.

ephemeralpush0 chrome

Anatomy

  • AThe mark, 15px, drawing. One loop per announcement, then it holds fully drawn. The draw is the entrance animation — nothing slides.
  • BThe class rail. A 3px vertical stroke in the class colour, between the mark and the text. It is the only status colour in the component.
  • CThe sentence. Actor in medium weight, then the past-tense clause. Single line, ellipsised — if it does not fit on one line, the string is wrong, not the component.
  • DThe overflow counter. "+7" appears when the queue is deeper than the line can serve. It is the only place this option admits it is dropping things.
Classes
Rail colour only. needs and blocked additionally hold for 6s instead of 2.6s and refuse to be superseded; the other three yield immediately.
The mark
Draws once per announcement, 1.5s, then holds. Never loops while idle, so it is never a spinner. Under a burst it drops to one draw for the whole burst.
Under load
Fails honestly. 12 events in 3s become 1 visible line plus "+11". The line shows the highest-priority event, not the newest. Everything else is only in the ledger.
Quiet paths
Focus mode: only needs and blocked appear. DND: nothing appears. Reduced motion: no draw, no slide — the line simply is there, then is not.
Access
The visible line is aria-hidden. A parallel role="status" region announces polite classes; a separate role="alert" handles blocked. SR hears: "Blocked. Egress guard. Blocked 2 contract pages from reaching an external model. Nothing left Riyadh."
Cost
Lowest. One element, one SVG, opacity + transform only — both compositor properties. No per-frame work when idle. ~40 lines of CSS, no new component in the OS shell.
02

Presence

A persistent mark whose state is the message. Breathing when idle, drawing when working, ringed in the class colour when something landed. Notification as presence rather than as text.

statepullalways on

Click the mark in the stage to expand it.

Anatomy

  • AThe mark, 24px, permanent. Bottom-right of the desktop, above the dock. Three states and nothing else: breathing (5.4s opacity drift, idle), drawing (1.9s loop, work in flight), held (fully drawn, still).
  • BThe ring. A 2px ring in the class colour of the most consequential unseen event. It fades in over 500ms and stays until you look. This is the whole message.
  • CThe count. Appears only when more than one thing is unseen — per §07, a count is a thing you clear, so it has earned a badge. Below two, there is no badge at all.
  • DThe expansion. Click or ⌥N: the last four announcements, dotted by class, ~110 characters each. Escape closes. This is the only text this option ever shows.
Classes
Ring colour = highest-priority unseen class. A blocked event also stops the breath entirely — stillness is the alarm. That reads at a glance, at any size, with no text.
The mark
The whole option is the mark. Speed encodes state exactly as desktop-vision §07 specifies: 5.4s = idle, 1.9s = working, 0.85s = closing out, held = done.
Under load
Survives untouched. 12 events do not queue — they update one ring and one integer. The cost is total: you learn that five things happened and nothing about what they were.
Quiet paths
Focus: the ring still tints, the count still counts, nothing pops. DND: the mark drops to breathing only, ring suppressed until you open it. Reduced motion: no breath, no draw — a static mark plus a static ring; state moves to a title and the expanded list.
Access
The mark is aria-hidden; a labelled button wraps it — "Console activity: 5 new, 1 needs you. Activate to review." Nothing auto-announces except blocked. This is the quietest option for a screen reader and the one that most requires the expansion to be genuinely good.
Cost
The one with real per-frame cost — stroke-dashoffset is not a compositor property, so an always-looping mark repaints a small SVG every frame, forever. Mitigations are mandatory: pause on visibilitychange, pause after 20s idle, and fall back to a two-step opacity pulse (which is composited) on low-power. Measured on one 24px mark this is negligible; it would not be at 58px behind a blur.
03

The ledger

A running, grouped, timestamped record in a rail: what ran, what it touched, what it wrote, residency and approval state on every row. Reads like a flight recorder.

recordpullaudit

Anatomy

  • AThe header. The mark at 12px, the word "Activity", and a live count. The mark draws once when the rail opens and never again — in a record, animation is noise.
  • BThe row. Monospace timestamp · class rail · actor in 650 weight · the sentence. Fixed grid, so 40 rows scan as a column of times, not a wall of text.
  • CThe tags. Residency (private), egress (blocked) and approval state (needs you) per row. This is the only option that shows sovereignty state on every single line, which is why it is the compliance answer.
  • DThe grouping. Three or more events from one actor within 60s collapse to one row with "· 4 more". Expanding is a click, and the underlying rows are never discarded.
  • EDay dividers. Sticky, so an overnight batch reads as "last night" rather than as an alarming pile.
Classes
2px rail per row plus a tag. Deliberately low-contrast: in a list of 40, saturated per-row colour is unreadable. needs rows float to a pinned "Waiting on you" group at the top — the only reordering allowed.
The mark
Header only, one draw on open. It signs the record; it does not narrate it.
Under load
Survives perfectly — it is a list. 12 events become 12 rows, or 4 rows once grouping fires. But it is a pull surface: nothing about the burst reaches you unless you were already looking at the rail.
Quiet paths
Unaffected by focus and DND by definition — it never pushes. That is its strength and its whole limitation.
Access
role="log" aria-live="off", navigable as a list, each row a landmark. SR reads a row as: "09:04. Wrote. Mail agent. Drafted a reply to Al-Rashid about the C2 rebar variation. Not sent, it is in Drafts. Private. Two actions available." Nothing is ever announced unbidden.
Cost
No per-frame work at all. The cost is space — a permanent rail is ~280px of desktop — and DOM growth: past ~200 rows it needs windowing. Replaces #notifPanel rather than adding to it, so net component count goes down.
04

Card stack

Discrete cards that collapse into a pile, the mark as sender, inline Undo / View / Approve, and a burst merged into one digest card.

pushactionablefamiliar

Anatomy

  • AThe sender row. Mark at 13px, actor name, relative time. The mark identifies Console as the sender the way an avatar does — it does not animate here. This is the one place the brand appears per card, so it must be still.
  • BThe class edge. A 3px full-height left edge. At a glance the pile reads as a colour histogram of your morning.
  • CInline actions. Approve / Reject / Undo / Open. This is what no other option has: the decision is reachable without navigating anywhere. Destructive and irreversible actions get the filled button in the class colour.
  • DThe pile. Beyond the visible few — three at desktop scale, two in this miniature — the rest stack with 4px offsets behind a "+n earlier" label. Click to fan out.
  • EThe digest card. A burst becomes one card: "12 things happened in 3 seconds", a per-class tally, and one action — "Review". The burst never becomes 12 cards.
Classes
Full treatment — edge, tinted ground for blocked, button colour, and dwell time. done auto-dismisses after 5s; wrote after 12s because it carries an Undo; needs and blocked never auto-dismiss.
The mark
Static sender identity, 13px. It draws once on the very first card of a session and is still thereafter. Resisting the urge to animate it per card is the entire discipline of this option.
Under load
Survives, but only because of the digest. Without it this is the worst option on the page — 12 stacked cards cover a third of the desktop. The rule that saves it: more than 3 events in 5 seconds, and everything non-actionable folds into one digest card while needs and blocked stay as individual cards, because you cannot approve a summary.
Quiet paths
Focus: only needs and blocked materialise; everything else goes straight to the pile, collapsed. DND: nothing materialises, the pile just grows. Reduced motion: no entry animation, no fan-out — cards appear and disappear.
Access
Each card is an article in a role="region". Actionable cards are not auto-announced into an interrupting region — instead the region is polite and the card is focusable, so a keyboard user tabs to it. SR: "Needs you. Vendor master cleanup. Wants to delete 41 duplicate vendor records. Irreversible — needs your sign-off. Approve button. Reject button." The digest announces once: "12 events. 2 need you, 1 blocked."
Cost
Medium. Transform and opacity only, so entry is composited — but the pile's fan-out is a layout change on up to 8 elements, and it must be transform-based rather than top-based or it will jank the same way the ⌘K backdrop-filter did. Genuinely new component, plus digest logic, plus an undo registry that has to be real.
05

Ambient

Almost no text. Activity reads as light on the dock icon, the menu bar and the window edge. The mark tints. Text only when you ask. The quietest option, and the house position.

ambientno chrome§07

Hover or click the mark in the menu bar to pull text.

Anatomy

  • ADock under-light. The icon of the app the event belongs to gets a soft box-shadow in the class colour. It brightens on the event and decays over ~8s. Two events on one icon = one brighter light, not two badges.
  • BWindow top hairline. 2px across the top of the affected window. If Mail wrote something, the Mail window is edged violet, whether or not it is focused.
  • CThe menu-bar mark, haloed. The mark keeps its own colours — it is never recoloured — but gains a soft halo in the class colour. Brand identity and status stay in different pixels.
  • DThe pull. Hover or click the mark: the last four lines, plain, no chrome. This is the only text in the option, and it exists on demand only.
  • EThe one exception. needs and blocked still get a red count badge on the dock, because per §07 those are things you must clear, and a count earns a badge. Everything else is light.
Classes
Light intensity carries recency, hue carries class, and a badge carries only the two classes that need clearing. Colour is the sole channel here, which is why the pull-text and the badge exist — see the accessibility row.
The mark
Menu bar only, 14px, still. It draws once at login. It gains a halo but is never tinted, filtered or recoloured, per the brand rule. The most restrained use of the mark of the five.
Under load
Survives trivially. 12 events become brighter light on 3 or 4 icons. There is no queue to overflow because nothing is queued. It is the only option where a burst looks better than a trickle — you can see the shape of the morning.
Quiet paths
It is the quiet path. Focus changes nothing. DND drops the badge and keeps the light. Reduced motion: the light does not pulse — it is either on or off, with a 500ms opacity fade, which is the one transition worth keeping.
Access
The weak point, and it must be answered head-on. Light alone is invisible to a screen reader and to the colour-blind. So: every event still writes to an aria-live="off" log, blocked still fires a role="alert", the dock badge exposes aria-label="Mail: 2 need you", and the pull-text is keyboard-reachable at ⌥N. Without those four, this option is unusable and must not ship.
Cost
Cheapest by a distance, and desktop-vision §07 already costed it: a box-shadow and a 3px pseudo-element per lit tile, zero frame cost, because the light either is or is not. The trap: making the glow pulse. An animated blurred box-shadow repaints a large area every frame and is exactly the mistake the ⌘K switcher's full-viewport backdrop-filter was. Fade in, fade out, never pulse.

What the burst is for

Twelve events in three seconds is not a stress test invented for a slide. It is 06:00 on a Tuesday: the overnight agents all report within a minute of each other, the SAP connector's first sync of the day fails, and yesterday's approvals roll over.

The burst sorts the five options into two families, and that split is the actual finding of this page. Push surfaces (Narrator, Card stack) have a queue, and a queue can overflow — they must drop, merge or digest, and each of those is a decision with a cost. State surfaces (Presence, Ledger, Ambient) have no queue: twelve events update one ring, append twelve rows, or brighten four icons. They cannot overflow because there is nothing to overflow.

Which is why the answer is unlikely to be one option.

Rate limiting, spelled out

One rule set, applied by the bus before any surface sees an event, so all five behave consistently:

  • Dedupe by id — the current double-row bug becomes structurally impossible.
  • Coalesce by actor — 3+ events from one actor inside 60s become one grouped event with a count.
  • Digest threshold — more than 3 events in 5s and every non-actionable event folds into one digest.
  • Never digest a decision — needsHuman events are exempt from every rule above. You cannot approve a summary.
  • One assertive announcement per 10s — a burst of blocked events produces one alert, not twelve. This is an accessibility requirement, not a nicety.
  • Floor of 1.2s between push animations — below that the eye reads flicker, not information.

06 · Recommendation

Ship a combination — and ship the words first.

The evidence does not support one winner, and pretending otherwise would produce a system that is either too loud on a normal Tuesday or too quiet on the one morning it matters. Three surfaces, each doing the job it is actually good at.

Default channel

05 · Ambient

Everything Console does, all day, is light on the dock and a halo on the mark. It survived the burst without a queue, it costs nothing per frame, and it is the position desktop-vision §07 already argued for. On an ordinary Tuesday you should be able to glance at the dock and know your morning without reading a single word.

Conditional: only ships with all four accessibility additions — the silent log, the role="alert" for blocked, labelled dock badges, and ⌥N pull-text. Light-only is not a design, it is an exclusion.

Promoted for humans

04 · Card stack

Promoted only for needs and blocked. This is the one option where the decision is in reach, and an approval you cannot act on where you read it is an approval you will act on late. Restricting cards to the two classes that require a human also resolves the §07 contradiction cleanly: a card exists because it carries an action, and an action is a thing you must clear — which §07 says has earned a badge.

In practice this is 2–5 cards a day, not 40. The digest rule stays in place for the mornings when it is not.

The record

03 · Ledger

Replaces #notifPanel behind the same clock button — so it costs one component rather than adding one. It is the only surface that carries residency and approval state per row, which for a sovereign on-prem deployment is not a nicety; it is the artefact an auditor asks for. It never pushes, so it never competes with the other two.

Net component count across the whole proposal: +2 (ambient light, actionable card), −1 (the current Notification Centre), −1 (the thought stream folds into the ledger as its own filter).

What I would fold in, not ship

02 Presence should not ship as a separate surface — it should become Ambient's mark. The menu-bar mark already needs a halo; giving it Presence's three speeds (breathing / drawing / held) and its click-to-expand costs almost nothing extra and gives Ambient the one thing it lacks, which is a place to put the mark's animation. That also concentrates the per-frame cost into a single 14px SVG with a hard pause rule, rather than spreading it.

01 Narrator should not ship as a surface either — but it is the most valuable thing on this page, because its copy standard is what all five run on. Keep the sentence, drop the pill.

Order, and what it costs

  1. The event schema and the copy standard. Half a day, no pixels. Give notifPush a class, an actor and an id; rewrite the ~70 existing toast strings to the seven rules; move responses and tips out of the stream. This alone fixes the duplicate-row bug and removes about a third of the traffic. Everything else is blocked on it; nothing is blocked by it.
  2. Ambient. ~1.5 days. A box-shadow, a pseudo-element and a decay timer. Zero frame cost. Ship the four accessibility additions in the same commit or not at all.
  3. The actionable card, needs + blocked only. ~3 days of the five, because restricting it to two classes removes the pile, the fan-out and most of the digest.
  4. The ledger, replacing the Notification Centre. ~3 days. Last, because it is the pull surface — nobody is worse off while it is still the old panel.

Token change: one new colour, --ev-blocked. The other four map onto --private, --public, --signal and --cyan, which Console already ships.

Three things I would flag before you decide.

1 — The mark is going to be asked to be a spinner, and it must not be. The brief for §1b of the addendum makes the mark the thinking indicator, which is right. But a mark that also announces every completion, every write and every failure animates almost continuously, and a logo that never stops moving stops being a logo. The rule that holds the line: the mark animates for work in progress and holds still for work that is finished. An announcement is by definition finished.
