What the AI-OS competition is actually doing

Nine products that are each solving one slice of "an AI that runs your work" — agent teammates, agentic browsers, self-hosted multi-model UIs, ambient life-management. None of them is a desktop-OS metaphor. This is the research behind Console (app-7) — the ideas worth taking from each, and concretely how Console folds them in so it reads as an AI-native operating environment, not a ChatGPT or Claude skin.

This is a research/reference document, not a build. Product descriptions below are synthesized from each company's own site and public docs as of August 2026. The "How Console does this" cards describe what's planned for apps/app-7-console.html — see that file for what's actually implemented.

Cohere OS

cohere-os.com

Despite the name, Cohere OS has no desktop, no windows, no icons at all — it's a background life-management service delivered through voice notes, texts, and scheduled calls. "The experience isn't using a tool. It's having a team that knows you." That philosophy — proactive, ambient, low-friction — is the real takeaway, not any visual pattern.

What it does

  • Connects email, calendar, Slack, finance apps; triages, drafts, tracks spend
  • Scheduled proactive briefings: 6am morning brief, 9am meeting prep, 6pm wrap
  • Persistent memory with a decision-history/reasoning trail
  • You give "occasional feedback" — voice note, text, call — nothing else

The idea worth taking

It never waits to be asked. Value shows up on a schedule, unprompted, and the user's only job is a light-touch reaction. Most AI products (including MagnaVERSE's chat surface today) are entirely pull-based — you have to remember to open the app and ask.

How Console does this

Desktop widgets aren't decoration — they're scheduled push. A morning-brief widget assembles overnight PO/schedule/agent activity into one card before the user opens anything; a "next automation" widget counts down instead of waiting to be queried. The dock's contextual zone surfaces the most urgent thing unprompted. Chat stays pull-based for exploration, but the desktop itself becomes the ambient layer Cohere OS is describing.

02

Lindy

lindy.ai

An AI teammate that lives in Slack, connects to 1,000+ tools, and does real multi-step work — updating a CRM, posting to a channel, sending an email, all from one instruction. Its two sharpest ideas: mandatory approval before anything changes, and skills taught by demonstration once and shared with the whole team.

What it does

  • "Lindy asks before it alters anything" — read-only lookups run free, writes need a human yes
  • 40+ prebuilt skills; "do something once, save it as a skill" for custom ones
  • Editable plain-text memory file the team can read and correct
  • Joins meetings as a named participant, transcribes, makes them queryable

The idea worth taking

Approval-gating isn't a one-off feature bolted onto a public/private switch — it's a consistent rule applied to every write action, everywhere, so trust compounds instead of being re-earned per feature.

How Console does this

MagnaVERSE already has one great approval-gate: the sovereignty guardrail before a thread with internal data goes Public. Console generalizes that pattern OS-wide — any agent action that writes (updates a PO field, sends a message, posts an automation) grows an inline confirmation bar at the point of action, the same visual language every time, instead of a single special-cased modal. And "Record a Skill" becomes a Console-level capability: demonstrate a task once in any window, save it, and it shows up as a new Spotlight-searchable action.

MultiOn

docs.multion.ai

Positions itself as the "Motor Cortex" for AI — an API that turns natural-language instructions into real browser actions: clicking, filling forms, scrolling, extracting structured data, at scale, with proxy/bot-detection handling for reliability.

What it does

  • Agent API: natural language → autonomous web actions in a remote browser session
  • Full-page structured data extraction (LLM-driven scraping)
  • Chrome extension for local human-agent handoff
  • Parallel agent execution across many sessions/pages at once

The idea worth taking

The web itself is a tool surface an agent should act on directly — not just a thing the user copy-pastes context out of into a chat box.

How Console does this

A dedicated Browser Agent app/window — a genuinely new 8th icon beyond the four originally named — where you describe a task ("check if the rebar supplier's portal shows a new delivery date") and the agent drives a sandboxed session, showing its steps live in the window (same scripted-transcript technique as Magna Code's chat pane), gated by the same approval rule as any other write action.

04

CrewAI

crewai.com

An enterprise multi-agent orchestration platform — build "crews" of agents that collaborate on a workflow, with centralized governance so platform teams keep control even as business users build their own agents. Claims 450M+ monthly agentic workflow runs and 65% Fortune 500 adoption.

What it does

  • Multi-agent "crews" that divide and collaborate on complex work
  • Unified build+runtime platform for both engineers and business teams
  • Centralized governance/oversight over what agents are deployed
  • Cloud platform and an open-source path for technical users

The idea worth taking

Agents aren't solo — real work needs several specialized agents handing off to each other, and an enterprise needs to see and govern the whole crew, not just one agent at a time.

How Console does this

The existing Agents app already shows individual agents with delegation between them (e.g. the PO Slippage Watch ↔ Risk Research Agent mutual handoff built earlier this session). Console's Agents window makes that a first-class "crew view" — a visual delegation map is the window's default view, not a buried detail — and every governed action a crew takes routes through the same OS-wide approval rule from Lindy's playbook above, so "centrally governed" is true by construction, not a separate admin panel.

05

Zapier Central

zapier.com/blog

AI bots that work "more like teammates than programs" — connect a knowledge source, teach behavior in plain language, then chat with the bot to run it, with 6,000+ app connectivity through Zapier's existing ecosystem. No code, three steps.

What it does

  • 3-step setup: add data → teach behavior → chat to run
  • Bots operate with or without the user present (background execution)
  • Multiple specialized bots per user for different jobs
  • Chat is the entire control surface — no separate builder UI to learn

The idea worth taking

Building an automation shouldn't feel like a different product from using one — the same chat window that runs your bot is the one that created it.

How Console does this

Spotlight (⌘K) doubles as the automation builder: typing "every morning, summarize P6 slippage and post it to Automations" creates the automation right there, no separate wizard, then the same query surface lets you inspect or edit it later. This is also the cheapest of all the researched ideas to fold in, since Console already plans to port app-4's command palette as its launcher.

Perplexity Comet

perplexity.ai/comet

A Chromium browser with an AI assistant living natively in the sidebar — aware of the current tab, retaining context across the session, and answering questions across all open tabs at once ("what do these tabs have in common?"). A separate Agent mode acts autonomously: books flights, fills forms, manages subscriptions.

What it does

  • Sidebar assistant: summarizes, answers, cites, translates — always present
  • Cross-tab context awareness, not just single-page
  • Comet Agent: autonomous multi-step task execution
  • Free across macOS/Windows/Android/iOS, no account required for core features

The idea worth taking

Context that spans multiple open surfaces at once is something only the browser/OS layer can see — a single-page chatbot structurally can't answer "what do these have in common," because it only ever sees one conversation.

How Console does this

This is the single strongest argument for building app-7 as a real multi-window OS rather than another chat surface: Spotlight/the floating companion can be asked "compare what's in this Knowledge window and that Chat thread" and answer across window boundaries, because the OS layer — uniquely — can see every open window's content. No other MagnaVERSE prototype can do this by construction.

Littlebird

littlebird.ai

A "second brain" that passively watches your active window and listens in meetings, so you never re-explain context. "Hummingbird" is a floating sidebar summonable from any app without switching windows. Memory renders as a magazine-style dashboard of cards, not a linear chat log.

What it does

  • Passive observation model — no manual paste-in of context required
  • Hummingbird: a floating, always-accessible companion over any app
  • Magazine-style memory dashboard (tasks, emails, focus areas) instead of chat
  • Drafts emails/docs "in your voice" from learned writing patterns

The idea worth taking

The assistant shouldn't live inside one app's window — it should float above every app, summonable anywhere, because the friction that kills AI adoption is switching context to go ask it something.

How Console does this

A persistent floating companion orb — distinct from the dock and from Spotlight — sits above every window and can be summoned with a click or shortcut regardless of which app has focus. It's the same underlying assistant as Chat, just always-reachable without opening a Chat window first, directly answering Littlebird's friction argument.

08

BrowserOS

browseros.com

An open-source, Chromium-based browser billed as "a privacy-first alternative to ChatGPT Atlas and Perplexity" — AI agents run locally, your browsing history and API keys never leave your machine, and it supports 11+ model providers including fully local models via Ollama/LM Studio.

What it does

  • Local-first agent execution — "not in some corporate cloud"
  • User owns their API keys and automations
  • Chromium fork — existing Chrome extensions keep working
  • Free, open-source, macOS/Windows/Linux

The idea worth taking

"Your data, your compute, your control" is a genuine trust differentiator right now, not just a compliance checkbox — several products in this list are explicitly positioning against cloud-only competitors on exactly this axis.

How Console does this

MagnaVERSE's sovereignty system already is this story, more concretely than BrowserOS's marketing copy — Private tier means real on-prem GPUs in Riyadh DC-1, not just "an API key you hold." Console makes that the OS's headline, not a per-thread detail: the menu-bar sovereignty pill is permanent chrome, and an "About Console" panel states the local-compute story in the same plain terms BrowserOS uses, because MagnaVERSE can back the claim with an actual data-residency architecture.

Open WebUI

openwebui.com

A self-hosted, ChatGPT-style interface for any LLM backend (Ollama, OpenAI-compatible APIs). Native RAG with source citations, a Pipelines plugin framework for custom Python logic, multi-model switching mid-conversation, and full RBAC so a team can share one deployment safely.

What it does

  • RAG built-in, no add-ons: upload docs, get cited answers
  • Pipelines framework: custom functions, rate limits, content filtering, translation
  • Switch models mid-chat; voice/video chat; image generation hooks
  • Multi-user roles/permissions for shared team deployments

The idea worth taking

Model choice and access control are core product surfaces, not settings buried three menus deep — a team deployment lives or dies on RBAC being visible and trustworthy.

How Console does this

MagnaVERSE already has a real model picker (Kimi/DeepSeek/Qwen/Nemotron) and a Skills/MCP framework — Console's Settings window elevates permissions/roles (already one of the 12 Settings panes) to sit alongside the model picker in the same visual tier, so "who can do what, on which model" reads as a first-class OS control, matching Open WebUI's instinct that this isn't a niche admin page.

10

The Console thesis

Nine products, nine different slices of "AI OS." None combines them. Console's bet is that the desktop-OS metaphor is the one shape that can hold all nine ideas at once — because it's the only one of MagnaVERSE's seven prototypes with more than one surface open at a time.

from Cohere OS

Proactive desktop widgets

Scheduled briefings surface unprompted on the desktop itself, not just on request in Chat.

from Lindy

OS-wide approval gate + Record a Skill

Every write action gets the same inline confirmation; demonstrate once, it's a Spotlight action forever.

from MultiOn / BrowserOS / Comet

Browser Agent app

An 8th window: describe a web task, watch a sandboxed agent execute it, same approval gate.

from Comet

Cross-window context

Spotlight/the companion can answer questions spanning multiple currently-open windows — only possible because it's an OS, not a single chat page.

from Littlebird

Floating companion, above every app

Summonable from any window without opening Chat first — the same assistant, zero switching cost.

from CrewAI

Crew view as the Agents default

Delegation between agents is the headline of the Agents window, not a buried detail.

from Zapier Central

Spotlight doubles as the automation builder

Describe the automation in the same launcher that runs everything else — no separate wizard.

from BrowserOS + Open WebUI

Sovereignty and access control as permanent chrome

The menu-bar tier pill and Settings' model/RBAC panes are always-visible OS surfaces, not settings buried three menus deep.
